# consultant-api — клиент КонсультантПлюс (cloud.consultant.ru)

CLI-клиент к веб-сервису КонсультантПлюс в рамках подписки пользователя. **Задача — быстро находить нужные
документы по полнотексту и основным фильтрам** (текст, реквизиты, дата, принявший орган, вид документа, тематика,
статус, судья, категория спора и др.), получать актуальную редакцию или редакцию на дату и выгружать документ так,
чтобы его можно было читать по статьям. Клиент отправляет те же запросы, что веб-интерфейс, поэтому состав и качество
результата такие же, как в браузере, а выполняется за секунды и без кликов. Им пользуются любые skills и обычные
вопросы в терминале; вывод — JSON.

**Статус:** рабочий, проверен вживую (19.10.2026) на законодательстве и судебной практике.

## Когда использовать

| Задача | Инструмент |
|---|---|
| Нормативный акт в официальной публикации, быстрая загрузка без подписки | [tools/pravo](../pravo/README.md) |
| Поиск по полнотексту и реквизитам, судебная практика, комментарии, актуальная редакция и редакция на дату, выгрузка и разбор документа | **consultant-api** (этот инструмент) |
| Нужна функция, которой в клиенте нет (кем цитируется, похожие документы, поиск внутри документа, формы документов, проекты актов), или пользователь хочет работать в браузере | [tools/consultant-browser](../consultant-browser/README.md) |

Порядок источников — в AGENTS.md: сначала локальный кеш `docs/refs`, затем `pravo`, затем `consultant-api`, затем
(запасной) `consultant-browser`, затем открытые источники с обязательной пометкой.

## Быстрый старт для агента

1. Проверить сессию: `python -X utf8 tools/consultant-api/consultant.py auth status`. Если `logged_in: false` — попросить
   пользователя запустить в **своём** терминале `python tools/consultant-api/consultant.py auth login` (логин и пароль
   вводит он; агент их не просит, не вводит и не читает вкладку терминала, пока идёт ввод).
2. Найти → посмотреть список → выбрать → выгрузить и разобрать (рецепты ниже).
3. Вернуть пользователю найденное **вместе с условиями поиска** (`conditions`) и охватом; слот подключения освобождается
   автоматически после каждой команды.

Все команды: `python -X utf8 tools/consultant-api/consultant.py <команда> ...` (`-X utf8` нужен в Windows-консоли).
Общие флаги: `--pretty` (форматированный JSON), `--min-interval` (пауза между запросами, по умолчанию 0,8 с).

## Рецепты

**Найти норму по цитате.** `quick --text "5.35.1 КоАП"`: ранжированная смешанная выдача, первым идёт сам кодекс, затем
комментарии и ситуации. Подходит, когда известна ссылка («ст. N такого-то закона»), а не документ.

**Найти документ по реквизитам.**
```
search --number "127-ФЗ" --doctype "Федеральный закон" --list 5
search --name "О несостоятельности (банкротстве)" --text-mode phrase --doctype "Федеральный закон" --list 5
search --date 26.10.2002 --doctype "Федеральный закон" --list 5
```

**Найти акты по тексту и фильтрам (законодательство).**
```
search --div LAW --text "утверждение устава" --text-mode doc --organ "Правительство РФ" \
       --doctype "Постановление" --date-after 31.10.2023 --status current --list 10
list --search <search_id> --node RZR --offset 0 --limit 20
```

**Судебная практика по вопросу.**
```
search --div ARB --text "субсидиарная ответственность" --text-mode doc --date-after 01.01.2023 \
       --status current --status lost --list 10
search --div ARB --text "аренда" --dispute "Аренда или субаренда зданий и сооружений (в т.ч. помещений)" \
       --claim "Требования арендодателя" --date-after 01.01.2025 --status current --status lost
```
Фильтры раздела ARB: `--organ` (суд), `--judge`, `--result` (результат рассмотрения), `--dispute`/`--claim`
(категория спора и требование), `--number` (номер дела/документа), `--date*`. Дерево `tree` в ответе `search`
показывает, где именно найдено; выбирайте узел: `list --search <id> --node ARB`.

**Редакция на дату события** (важно для норм, действовавших в прошлом):
```
edition --base LAW --n <n> --on-date 15.03.2019         # какая редакция действовала
export  --base LAW --n <n> --on-date 15.03.2019 --split  # выгрузить и разобрать именно её
```

**Не утратил ли документ силу / актуальная ли редакция.** `edition --base LAW --n <n>`: `is_current`, `ineffective`,
`current` (номер актуальной редакции).

**Получить документ целиком для чтения и `docs/refs`.** `export --base LAW --n <n> --split` подменяет номер
актуальной редакцией, проверяет целостность и разбирает документ в каталог markdown (skill `legal-doc-splitter`);
дальше читать по статьям. Сохранять в `docs/refs` только после согласия пользователя (AGENTS.md); в ответе есть готовое
`refs_entry_suggestion`.

**Сузить слишком большой результат.** Добавить `--organ`, `--doctype`, `--date-*`, `--topic`, режим `--text-mode phrase`
или `near=N`, выбрать нужный узел дерева (`--node`).

## Как формулировать поиск (чтобы результат был не хуже браузера)

**Полнотекст.** Основное условие — `--text` (по тексту) и `--name` (по названию). Режим `--text-mode` меняет смысл
запроса, поэтому для точных задач задавайте его явно. На запросе «утверждение устава» (все разделы):

| Режим | Смысл | Найдено |
|---|---|---|
| `auto` (по умолчанию) | сервер подбирает параметры («умный» режим) | 171 025 |
| `doc` | слова в документе, любой порядок, все формы слов | 269 479 |
| `paragraph` | слова в одном абзаце | 102 878 |
| `near=5` | в пределах 5 слов | 32 705 |
| `phrase` (= `"в кавычках"`) | словосочетание | 11 912 |
| `phrase --exact-forms` | словосочетание в точно заданных формах | 1 675 |

Флаги: `--exact-forms` (строго заданные формы слов; сужает на порядок), `--no-synonyms`, `--no-links`. Для широкого
охвата берите `doc`, для точного — `phrase`/`near=N`. **Операторы** внутри текста: `"фраза"`, `(группировка)`,
`устав*` (усечение), `\И` (по умолчанию), `\ИЛИ`, `\КРОМЕ`. Пример: `(устав \ИЛИ положение) \И утверждение`. Других
операторов нет, близость слов задаётся режимом. Нулевой результат: ослабьте режим (`doc`), уберите `--exact-forms`,
проверьте фильтры и даты.

**Реквизиты и справочные фильтры.**
- `--date` (точная), `--date-after` (позже чем), `--date-before` (раньше чем), `--date-from` + `--date-to` (диапазон),
  формат `ДД.ММ.ГГГГ`.
- `--organ`, `--doctype`, `--number`, `--judge`: значения проверяются по справочнику сервера (`dict --field organ
  --filter "Верховный"` покажет варианты). Неоднозначное название даёт ошибку `usage` со списком кандидатов
  (`data.candidates`): выбирайте осознанно, клиент не берёт «первое попавшееся».
- `--topic` (тематика, LAW) и `--result` (результат рассмотрения, ARB) — по названию узла дерева (`tree --field topic
  --filter "Банкротство"`); несколько значений можно повторять.
- `--status`: `current` (действующие), `lost` (утратили силу), `pending` (не вступили) или название.
- `--raw ПОЛЕ=ЗНАЧЕНИЕ` — готовое значение для поля, которого нет в именованных опциях (поля раздела — `fields --div X`).

**Охват баз (важно).** Без критерия статуса поиск идёт по ограниченному набору баз; критерий статуса расширяет охват
(добавляются крупные судебные базы). Для полной судебной практики указывайте `--status current --status lost`.
Итоги с критерием статуса и без него не сравнивайте: охват разный. Настройку «Выбор баз» пользователя клиент не меняет.

**«Всего» — по всем разделам.** Число `total` и дерево `tree` показывают разбивку по разделам и базам. Список
`list` возвращает один узел дерева: по умолчанию основной, нужный задавайте `--node` (код базы, например `RZR`, `ARB`, или
название узла). Страница списка — 50 документов (`--offset`, `--limit`). Порядок документов — как у сервиса (обычно новые
первыми); настраиваемой сортировки пока нет.

**Редакции.** Документ идентифицируется номером редакции. «Публичный» номер (например, у НК РФ) ведёт на первоначальный
текст, поэтому `export` по умолчанию подменяет его актуальным; `--exact` отключает подмену, `--on-date` берёт редакцию на
дату. Для анализа событий прошлого всегда проверяйте редакцию на дату события, а не последнюю.

**Проверка найденного.** Сниппет и название — не текст нормы. Прежде чем ссылаться на документ или статью, прочитайте
фактический текст (`export --split`, затем `read` в skill `legal-doc-splitter`). Примечания КонсультантПлюс в тексте
помечены `> [КП]`: это комментарий системы, а не норма. В ответе пользователю указывайте условия поиска (`conditions`),
охват (статус) и редакцию.

## Команды и параметры

| Команда | Что делает |
|---|---|
| `auth login [--remember]` | интерактивный вход (ввод виден при наборе, пароль после Enter закрывается звёздочками) |
| `auth status` | жива ли сессия и когда истекает (слот не занимает) |
| `auth forget` | удалить локальную сессию |
| `slot release` | освободить слот этой сессии |
| `fields --div LAW\|ARB\|…` | поля карточки раздела (номер, название, тип) |
| `dict --div X --field F [--filter …] [--limit N]` | значения справочника поля (орган, вид документа, номер, судья, статус) |
| `tree --div X --field topic\|result --filter …` | узлы деревьев-справочников с путями и кодами |
| `dispute --court arb\|soj [--filter …] [--claims-for КОД]` | категории спора и требования с кодами |
| `quick --text … [--limit N]` | быстрый поиск по естественному запросу или цитате |
| `search …` | поиск по карточке: `search_id`, `total`, дерево по базам, при `--list N` — первые документы |
| `list --search ID [--node …] [--offset N] [--limit N]` | список документов найденного |
| `edition --base B --n N [--all] [--limit K] [--on-date …]` | актуальная редакция, список редакций, редакция на дату |
| `export --base B --n N [--format …] [--exact] [--on-date …] [--out DIR] [--split] [--split-dir DIR]` | выгрузка документа |

Параметры `search`: `--div` (LAW — законодательство, по умолчанию; ARB — судебная практика; AP, PAP, PRJ — другие
разделы, поля смотрите `fields`), `--text`, `--name`, `--text-mode`, `--exact-forms`, `--no-synonyms`, `--no-links`,
`--number`, `--date`, `--date-after`, `--date-before`, `--date-from`, `--date-to`, `--organ`, `--doctype`, `--topic`,
`--result`, `--judge`, `--status`, `--court`, `--dispute`, `--claim`, `--raw`, `--list`. Повторяемые: `--number`,
`--organ`, `--doctype`, `--topic`, `--result`, `--judge`, `--status`, `--dispute`, `--claim`, `--raw`.

Форматы выгрузки: `fb2` (по умолчанию, структура), `utxt` (простой текст UTF-16, без лимита размера), `html`, `docx`,
`rtf`, `epub`, `pdf`, `xml2003`. Разбор в каталог (`--split`) — только для `fb2`.

## Что возвращается

`search` → `{"search_id", "div", "total", "conditions": [{field, param}], "default_node", "tree": [{node, level, name, base,
count}], "list": {...}}`. `list` → `{"search_id", "node", "total_in_node", "offset", "count", "items": [{order, base, n,
requisites, title, snippet}]}`; `n` — номер документа для `edition` и `export`. `export` → `{"path", "format", "bytes",
"base", "n", "requested_n", "title", "edition_date", "resolution", "checks", "split": {...}, "refs_entry_suggestion"}`;
`checks` — проверки целостности (XML корректен, файл закрыт, длина совпала).

## Контракт ошибок

Успех: JSON в stdout, код 0. Ошибка: JSON `{"error": {"code", "message", "hint", "data"}}` в stderr и код возврата.

| Код | Возврат | Что значит и что делать |
|---|---|---|
| `usage` | 2 | неверные параметры; смотреть `data.candidates` (варианты значений) |
| `auth_required` | 3 | нужен вход: попросить пользователя запустить `auth login` |
| `slot_busy` | 4 | единственное подключение занято (обычно открыт КонсультантПлюс в браузере): пользователь нажимает «Выйти» или ждёт до 30 минут простоя |
| `service_error` | 5 | ошибка сервиса (код в `code`: `core_libo` — неверное значение поля, `nothing_found` — ничего не найдено) |
| `network_error` | 6 | сеть; повторить позже |
| `not_found` | 7 | нет такого поиска, узла, редакции |
| `export_incomplete` | 8 | выгрузка не прошла проверку целостности (`data` — какие проверки); повторить или взять `utxt` |
| `agreement_required` | 1 | сервер просит принять условия: чаще опечатка в логине (так он отвечает и на несуществующий), иначе решает пользователь в браузере |

`nothing_found` — это не сбой: ослабьте условия (режим `doc`, меньше фильтров).

## Принципы и ограничения безопасности

- **Вход делает человек.** Логин и пароль нигде не сохраняются: на диск попадают только куки сессии и служебный `rnd`
  (`secrets/consultant-session.json`, закрыт `.gitignore`). Файл сессии не читать, не печатать, не коммитить.
- **Состояние учётной записи не меняем никогда:** не принимаем условия использования, не меняем настройки, закладки,
  папки, мониторинг, журнал. Клиент передаёт `NOQUERYLOG=1`, как сам сайт, чтобы поиски не писались в журнал.
- **Одно подключение на учётную запись.** Каждая команда занимает слот и всегда освобождает его; параллельные вызовы
  клиента выстраиваются в очередь. Браузер и клиент одновременно работать не могут.
- **Не нагружаем сервис:** запросы по одному, пауза между ними, повторы с задержкой. Не запускайте поиск «пачками».
- **Ничего не пишет в `docs/refs`:** файлы попадают в `.cache/consultant/` или в `--out`; сохранение в `refs` — решение
  вызвавшего skill вместе с пользователем.
- Клиент работает с подпиской пользователя через тот же веб-интерфейс, что и браузер; условия использования сервиса
  остаются на пользователе.

## Ограничения (что делать в браузере)

- **Не реализовано:** «кем цитируется» (документы, ссылающиеся на данный), похожие документы, поиск по тексту внутри
  документа, поля разделов `AP`/`PAP`/`PRJ`/`AM` не исследованы, постраничность быстрого поиска, настраиваемая
  сортировка. Для этого пользуйтесь [consultant-browser](../consultant-browser/README.md).
- Режим текстового поля `auto` — «чёрный ящик» сервера: для воспроизводимости задавайте режим явно.
- После 30 минут простоя сессия истекает: нужен новый `auth login` (вход без пароля по долгим кукам не проверялся).
- Время жизни `cacheid` поиска неизвестно: при устаревшем клиент сам перестраивает поиск один раз.

## Установка и устройство

```
pip install -r tools/consultant-api/requirements.txt
```

```
consultant.py              точка входа
consultant_api/
  cli.py                   команды, разбор аргументов, контракт ошибок
  client.py                слот, поля карточки, справочники, поиск, список, редакции, экспорт, разбор
  auth.py                  вход, хранилище сессии, замок «одна команда за раз», проверка сессии
  http.py                  запросы по одному, пауза, повторы; User-Agent Firefox 158 (зашит намеренно)
  cache.py                 кеш в .cache/consultant/ (карточки 7 дней, справочники сутки, сохранённые поиски)
  errors.py                ошибки с кодами и подсказками
```

Хранилища (в репозиторий не попадают): `secrets/` (сессия, см. `secrets/README.md`) и `.cache/consultant/` (кеш,
выгрузки в `exports/`, разобранные документы в `docs/`).
