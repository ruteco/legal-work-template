# docx-export — выгрузка документов в Word

## Статус

**Рабочий, проверен вживую (27.07.2026).** Конвертирует Markdown в `.docx` с
оформлением под российские юридические документы. Проверен на реальном
процессуальном документе (заключение по делу) и тестовом образце со всеми
поддерживаемыми элементами разметки (шапка, таблица, вложенные списки,
разрыв страницы, подписной блок).

## Зачем

Итоговые документы для клиента и для суда (заключения, отзывы, ходатайства,
заявления) нужны в Word. Писать под каждый документ отдельный скрипт на
`python-docx` — долго и неповторяемо. Этот инструмент позволяет держать текст
документа в Markdown (удобно править, видно в diff), а Word получать одной
командой.

Оформление по умолчанию соответствует обычным требованиям к процессуальным
документам: А4, Times New Roman 14 пт, поля 30/15/20/20 мм, полуторный
интервал, абзацный отступ 12,5 мм, выключка по ширине.

## Зависимости

`python-docx`. Если не установлен:

```
pip3 install --user python-docx
```

## Использование

```
python3 tools/docx-export/md2docx.py вход.md [выход.docx] [опции]
```

Если `выход.docx` не указан — файл создаётся рядом с исходником с тем же именем.

Примеры:

```
# простая выгрузка
python3 tools/docx-export/md2docx.py "задачи/эксперимент № 1/отчет.md"

# явное имя файла
python3 tools/docx-export/md2docx.py отзыв.md "Отзыв на требование ИФНС.docx"

# без абзацного отступа, одинарный интервал (для внутренних документов)
python3 tools/docx-export/md2docx.py памятка.md --indent 0 --spacing 1.0
```

### Опции

| Опция | По умолчанию | Назначение |
|---|---|---|
| `--font` | Times New Roman | основной шрифт |
| `--mono-font` | Courier New | шрифт для `моноширинных` фрагментов |
| `--size` | 14 | кегль основного текста, пт |
| `--header-size` | 11 | кегль шапки, пт |
| `--spacing` | 1.5 | межстрочный интервал |
| `--indent` | 12.5 | абзацный отступ, мм (`0` — без отступа) |
| `--para-space` | 6 | интервал после абзаца, пт |
| `--header-width` | 93 | ширина блока шапки, мм |
| `--margin-left/right/top/bottom` | 30/15/20/20 | поля страницы, мм |

## Поддерживаемая разметка

### Блочные элементы

| Разметка | Результат |
|---|---|
| `# Текст` | заголовок документа — по центру, полужирный |
| `## Текст`, `### Текст` | заголовок раздела — полужирный, с отступом |
| обычный абзац | выключка по ширине, красная строка |
| `- пункт` | маркированный список (вложенность — по отступу) |
| `1. пункт` | нумерованный список (нумерация берётся из текста как есть) |
| `\| a \| b \|` + строка-разделитель | таблица с границами, шапка полужирная |
| `\newpage` или `<!-- pagebreak -->` | разрыв страницы |
| `---`, `***` | пропускается (горизонтальные линии в документе не нужны) |

### Специальные блоки

Оформляются парой строк `:::имя` … `:::`

```
:::header
В Арбитражный суд города Москвы
115225, г. Москва, ул. Большая Тульская, д. 17

**Дело № А40-100500/24-100-100**
:::
```

- `:::header` (синоним `:::шапка`) — шапка процессуального документа: блок в
  правой части листа, кегль 11, одинарный интервал. **Строки не переносятся
  автоматически** — разбивайте их вручную так, чтобы каждая помещалась в
  ширину блока (`--header-width`, по умолчанию 93 мм ≈ 44 символа).
- `:::center` (`:::центр`) — блок по центру.
- `:::right` (`:::право`, `:::подпись`) — блок по правому краю, для даты и
  подписи.

### Строчное оформление

| Разметка | Результат |
|---|---|
| `**текст**` | полужирный |
| `*текст*` | курсив |
| `` `текст` `` | моноширинный (Courier New, на 1 пт мельче) |
| `[подпись](ссылка)` | остаётся только подпись, ссылка отбрасывается |

**Подчёркивания как разметка не поддерживаются намеренно.** В обычном Markdown
`__текст__` — полужирный, а `_текст_` — курсив. В юридических документах
постоянно встречаются строки для заполнения (`«___» _______ 2026 г.`,
`__________ / И.И. Иванов`), и такая разметка их съедала бы. Для выделения
используйте `**` и `*`.

## Ограничения

- Строки блока `:::header` не переносятся — следите за длиной вручную.
- Нумерация списков не пересчитывается: что написано в Markdown, то и попадёт в
  документ. Для юридических документов это правильно — нумерация пунктов часто
  задаётся по смыслу, а не по порядку.
- Вложенность списков — до 3 уровней.
- Изображения, сноски и колонтитулы не поддерживаются.

## Проверка результата

В окружении может не быть LibreOffice и pandoc, поэтому визуально отрендерить
`.docx` в PDF обычно не получается. Структуру можно проверить программно:

```
python3 -c "
from docx import Document
d = Document('файл.docx')
print('абзацев:', len(d.paragraphs), 'таблиц:', len(d.tables))
for p in d.paragraphs:
    if p.text.strip():
        print(p.alignment, '|', p.text[:80])
"
```

Перед отправкой документа клиенту или подачей в суд его всё равно следует
открыть в Word и просмотреть глазами.
