# API системы ГАРАНТ — выжимка спецификации (v1.7)

Составлено на основе `garant_api_v1.7.pdf` (официальный документ с garant.ru) через
`garant_api_v1.7.txt` (текстовая копия, `pdftotext -enc UTF-8 -layout`). Не является
официальной публикацией — при расхождениях ориентироваться на оригинальный PDF.

## Доступ и авторизация

- Базовый URL: `https://api.garant.ru/v1`
- Заголовки: `Accept: application/json`, `Content-Type: application/json` (кроме GET без тела)
- Авторизация: `Authorization: Bearer <token>`. Токен выдаётся **в личном кабинете
  администратора комплекта ГАРАНТ** (сам процесс получения кабинета в документе не
  описан — уточнять у менеджера Гаранта вместе с договором).
- Есть отдельный режим для локального продукта "Проксима" (свой базовый URL вида
  `http://<сервер>/api`, авторизация не требуется, только clientские документы из БВД) —
  в этом проекте не используется, в клиенте не реализован.

## Лимиты

- `find-hyperlinks` + `block-on-control/changed` — суммарно ≤ 1000 запросов/календарный месяц
- Экспорт документа (`download`, `download-odt`, `download-pdf`) — ≤ 30 документов/месяц
- `block-on-control/changed` (постановка на контроль) — ≤ 100 документов за один вызов
- `find-hyperlinks` — размер текста ≤ 20 МБ
- `prime/create-news` — нельзя запросить новости старше 1 года
- `topic/{id}` (информация о документе) — ≤ 300 запросов/месяц

## Эндпоинты

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/search` | Поиск документов по тексту или языку запросов |
| POST | `/snippets` | Релевантные фрагменты документа под текст запроса |
| POST | `/find-hyperlinks` | Простановка ссылок на упомянутые в тексте документы |
| GET | `/topic/{topic}/download` | Документ целиком, RTF |
| GET | `/topic/{topic}/download-odt` | Документ целиком, ODT |
| GET | `/topic/{topic}/download-pdf` | Документ целиком, PDF |
| GET | `/topic/{topic}/html` | Документ постранично, HTML-фрагменты |
| GET | `/topic/{topic}/entry/{entry}/html` | Конкретный пункт/абзац, HTML |
| GET | `/formula` | Изображение формулы (по base64 из `<img src>`) |
| GET | `/topic/{topic}` | Метаданные документа |
| POST | `/find-modified` | Проверка изменений по списку документов с даты |
| POST | `/block-on-control/changed` | Статус изменений по конкретным пунктам (URL) |
| GET | `/prime` | Дерево категорий ленты ПРАЙМ |
| POST | `/prime/create-news` | Новости ленты ПРАЙМ по категориям/датам |

### POST /search

```json
{
  "text": "44-фз о контрактной системе",
  "isQuery": false,
  "count": 30,
  "kind": ["001", "002"],
  "sort": 0,
  "sortOrder": 0
}
```

- `kind`: `001` федеральное законодательство, `002` региональное, `003` судебная практика,
  `004` пользовательские документы (нельзя сочетать с другими кодами — ошибка 400).
- `isQuery=true` — `text` разбирается как запрос на специальном языке (см. ниже), `kind` игнорируется.
- `sort`: `0` релевантность, `1` дата документа, `2` дата последнего изменения, `3` юридическая сила.
- `sortOrder`: `0` убывание, `1` возрастание.

Ответ: `{"documents": [{"name", "url", "topic"}]}`.

### Язык запросов (при `isQuery: true`)

```
& BOOL(& MorphoText(налог))                       — по словам в тексте
& BOOL(Date(20.01.2022;26.01.2022))                — по дате документа
& BOOL(& MorphoName(Конституция))                  — по словам в названии
& BOOL(| Type(Аттестат))                           — по типу документа
& BOOL(| Adopted(Органы власти г. Москвы))         — по принявшему органу
& BOOL(RDate(20.01.2022;26.01.2022))                — по дате регистрации в Минюсте
& BOOL(| Type(Акт)) & BOOL(| Number(44))            — комбинация реквизитов
&Correspondents(403127269 35020)                    — документы, ссылающиеся на topic/блок
&Respondents(57589736 21)                            — документы, на которые ссылается topic/блок
```

### Остальные методы (кратко)

- **`/snippets`** (POST): `{text, topic, correspondent?: {topic, entry}}` → `{snippets: [{relevance, entry, ancestors[]}]}`.
- **`/find-hyperlinks`** (POST): `{text, baseUrl}` → `{text}` с `<a href="{baseUrl}/#/document/$topic">`.
- **`/topic/{id}/download*`** (GET): бинарный файл (RTF/ODT/PDF), без тела запроса.
- **`/topic/{id}/html`** (GET) → `{items: [{number, text}]}` (text — HTML-фрагмент страницы).
- **`/topic/{id}/entry/{entry}/html`** (GET) → `{body}` (HTML одного пункта).
- **`/formula`** (GET, query-параметры `text`, `fmt=png`) → бинарное изображение.
- **`/topic/{id}`** (GET) → метаданные: `name, number, date, kind, category, status, active, territory, ...`.
- **`/find-modified`** (POST): `{topics: [id...], modDate, needEvents?}` → `{topics: [{topic, modStatus}], events?: [{date, type}]}`.
  `modStatus`: `1` изменён, `2` не изменён. `events[].type`: `1` включён в базу, `2` исключён,
  `3` признан утратившим силу, `4` внесены изменения, `5` восстановлен — коды `events[].type`
  распознаны из PDF с низкой уверенностью, сверить при первом реальном ответе.
- **`/block-on-control/changed`** (POST): `{fromDate, urlArray: [url...]}` → `{urlArray: [{url, modStatus}]}`.
- **`/prime`** (GET) → `{categories: [{text, id, children?}]}` (дерево тем).
- **`/prime/create-news`** (POST): `{categories: [id...], fromDate, toDate?}` → `{news: [{name, document: {url, topic, name}, paragraphs[]}]}`.

## Коды ошибок

Таблица в оригинальном PDF — многострочная, при автоматическом извлечении текста строки
местами сбились по столбцам. Общий смысл (перепроверить точное соответствие при первом
реальном ответе API или по оригинальному PDF):

- **400** — синтаксис/формат запроса неверный; для `find-modified`/`block-on-control` — если
  передано больше 100 документов за вызов; для `prime/create-news` — если `fromDate` отличается
  от текущей даты больше чем на год, либо разница `fromDate`↔`toDate` больше 10 дней.
- **401** — неверный или истёкший токен авторизации.
- **403** — нет прав на данный запрос (недостаточно разрешений у токена); для "Проксимы" —
  попытка получить документ не из Базы Внутренних Документов.
- **404** — документ не найден / категория не найдена.
- **423** — превышены месячные лимиты (см. раздел «Лимиты» выше).
- **429** — слишком много запросов, сервис временно недоступен.
