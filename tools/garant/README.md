# Интеграция с API системы ГАРАНТ (черновик)

## Статус

Нерабочий набор скриптов. Договора и токена доступа к API ГАРАНТ пока нет —
код написан по документации, но ни разу не вызывался против реального сервера.

## На основе чего написан код

`docs/garant_api_v1.7.pdf` — официальная спецификация "API. Версия 1.7",
скачанная с garant.ru. Это не OpenAPI/Swagger-файл (машиночитаемой схемы Гарант
не публикует), а PDF-документ с прозой и примерами запросов/ответов. Текстовая
копия — `docs/garant_api_v1.7.txt` (извлечена через `pdftotext -enc UTF-8 -layout`),
человекочитаемая выжимка — `docs/api-spec-summary.md`.

Из документа взяты реальные: базовый URL (`https://api.garant.ru/v1`), формат
авторизации (Bearer-токен в заголовке `Authorization`), пути и методы всех 13
эндпоинтов, JSON-схемы запросов/ответов с примерами, лимиты и коды ошибок.
Клиент (`scripts/garant_client.py`) реализует ровно это — без догадок за
пределами документа.

Что осталось неясным (пометить как TODO при первом реальном вызове):

- точный процесс получения токена (в документе сказано только "в личном
  кабинете администратора Вашего комплекта" — сам кабинет не описан);
- таблица кодов ошибок в оригинале — многострочная и при автоматическом
  извлечении текста местами сбилась по столбцам; соответствие кодов и причин
  в `api-spec-summary.md` может быть неточным — сверить с оригинальным PDF
  или с реальными ответами API;
- коды `events[].type` в `find-modified` распознаны с низкой уверенностью;
- отдельный локальный режим API ("Проксима", без авторизации, свой базовый
  URL) в скелете не реализован — в этом проекте не нужен.

## Структура

```
tools/garant/
  docs/                     спецификация API (pdf/txt/md)
  scripts/
    garant_client.py        клиент — вся логика вызовов API
    _common.py               общие мелочи для CLI (JSON-вывод, обработка ошибок)
    search.py                поиск документов
    topic_info.py             метаданные документа
    get_text.py               полный текст документа (HTML)
    download.py                скачать документ (pdf/rtf/odt)
    find_modified.py           проверка изменений документов
    requirements.txt
```

Никакого сервера/процесса нет — это обычные CLI-скрипты, вызываются напрямую.

## Как включить, когда появится доступ

```bash
pip install -r scripts/requirements.txt
export GARANT_API_TOKEN=...   # токен из личного кабинета комплекта
```

Примеры вызова:

```bash
python scripts/search.py "44-фз о контрактной системе" --kind 001 002
python scripts/topic_info.py 102004
python scripts/get_text.py 102004 --out ./102004.html
python scripts/download.py 102004 --fmt pdf --out ./102004.pdf
python scripts/find_modified.py 77682742 45069704 --since 2019-07-01 --events
```

Первый реальный вызов стоит сделать с `search.py` на простом запросе и
свериться с ответом API — при расхождениях поправить парсинг в
`garant_client.py`.

## Важно

Скрипты не пишут в `docs/refs` автоматически. По правилу из `AGENTS.md`
сохранение первоисточника локально требует подтверждения пользователя —
скачанный через `download.py`/`get_text.py` файл переносится в `docs/refs`
вручную, только после этого подтверждения.
