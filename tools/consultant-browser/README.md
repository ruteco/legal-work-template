# КонсультантБраузер — доступ к cloud.consultant.ru через браузер

## Статус

**Рабочий, проверен вживую (26.07.2026).** Не API, а работа через браузерный
инструмент (Browser pane) в личном кабинете КонсультантПлюс пользователя.
Официального публичного API у КонсультантПлюс нет (в отличие от
[tools/pravo](../pravo/README.md)) — доступ только через веб-интерфейс по
подписке пользователя.

## Почему через браузер, а не API

У КонсультантПлюс нет открытого API вроде publication.pravo.gov.ru. Единственный
способ получить документы — веб-интерфейс `cloud.consultant.ru`, доступный после
входа в личный кабинет пользователя (логин/пароль, подписка).

**Важное ограничение: агент не имеет права сам вводить пароль в форму входа**
(правило безопасности — ввод учётных данных запрещён). Поэтому вход в личный
кабинет всегда делает пользователь сам:

1. Агент открывает `https://login.consultant.ru/?authType=login` в Browser pane.
2. Пользователь сам вводит логин/пароль (и проходит капчу/2FA при необходимости).
3. Пользователь сообщает агенту, что авторизация выполнена.
4. Дальше агент работает в уже авторизованной сессии (`cloud.consultant.ru`) —
   ищет, открывает и читает документы.

Сессия сохраняется в Browser pane на время работы; повторный вход не нужен,
пока сессия не истекла или вкладка не была закрыта.

## Как искать документы

1. Открыть "Карточка поиска" (верхнее меню) — это основной инструмент
   структурированного поиска.
2. Переключиться на нужный раздел (вкладка сверху формы): "Законодательство"
   или "Судебная практика". Клик по названию вкладки (не по счётчику слева)
   переключает набор полей формы.
3. Для судебной практики полезные поля: "Принявший орган" (например,
   "Конституционный Суд РФ"), "Вид документа", "Дата", "Номер", "Текст
   документа".
4. **Важно:** поля вроде "Принявший орган" — это не обычные текстовые input,
   а классификаторы. Клик по полю открывает модальное окно с строкой поиска и
   списком чекбоксов; нужно ввести текст в строку поиска модалки, отметить
   нужный чекбокс и нажать "Применить".
5. После настройки фильтров — кнопка "Показать список документов". Результаты
   в судебной практике обычно уже отсортированы от новых к старым.
6. Открыть документ из списка одним кликом обычно показывает только
   всплывающее превью (тултип), а не переход на страницу документа.
   Через `javascript_tool` найти реальный `href` ссылки на документ
   (`document.querySelector('a[href*="n=<ID>"]')`) и перейти на него через
   `navigate` — так надёжнее, чем клик/двойной клик по ссылке в списке.

## Технические особенности (важно для автоматизации)

- **Клики по координатам ненадёжны.** `computer` с `coordinate` работает в
  масштабе скриншота, а скриншот — это уменьшенная копия реального viewport
  (например, скриншот 800×514 при viewport 1400×900). Прямой пересчёт
  координат на глаз даёт частые промахи. **Гораздо надёжнее** сначала вызвать
  `read_page` (`filter: interactive`), найти нужный элемент по `ref`, и
  кликать по `ref` — эти клики бьют в реальные координаты элемента напрямую.
- **Полный текст документа — во вложенном iframe.** Видимый в браузере текст
  постановления/определения рендерится не в основном документе, а в iframe
  с `src`, содержащим `document_inner.htm`. Обычный `get_page_text` его не
  захватывает. Текст нужно вытаскивать через `javascript_tool`:
  ```js
  const f = Array.from(document.querySelectorAll('iframe'))
    .find(f => f.src.includes('document_inner'));
  f.contentDocument.body.innerText;
  ```
  Если вывод обрезается инструментом (большой документ) — результат
  сохраняется в файл tool-результата; текст там — JSON-строка (с
  экранированием), декодировать через `json.loads`/аналог перед сохранением.
- **Прямая навигация по URL с "руками" вписанными параметрами (`rnd=`, `ts=`)
  не работает** — эти токены привязаны к конкретной странице/сессии и быстро
  устаревают, попытка вручную собрать URL по образцу из другого места чаще
  всего даёт "resource not found". Переходить только кликами по ссылкам
  интерфейса или по `href`, извлечённому через JS с текущей страницы.
- Строка поиска "Принявший орган" и подобные классификаторы: после клика на
  поле фокус уходит на `<tr class="x-page-card-field-list-row">`, а не на
  `<input>` — это ожидаемо открывает модалку выбора, а не позволяет печатать
  текст прямо в карточке.

## Когда использовать вместо tools/pravo или tools/garant

- `tools/pravo` — приоритетный источник для официальных нормативных актов
  (законы, кодексы, НПА) в аутентичном виде публикации.
- `tools/garant` — резерв, пока нет оплаченного доступа.
- **КонсультантБраузер** — использовать, когда нужны материалы, которых нет в
  открытых источниках pravo.gov.ru: судебная практика (в т.ч. КС РФ, ВС РФ,
  арбитражные суды), аналитика, толкования, подборки практики, кодексы с
  постатейными комментариями и т.п. — то, что покрывает подписка
  пользователя на КонсультантПлюс.

## Важно

Как и для остальных инструментов в этой папке, сохранение найденного
документа в `docs/refs` требует подтверждения пользователя (см. правило в
[AGENTS.md](../../AGENTS.md)), если пользователь явно не запросил сохранение
в той же задаче.
