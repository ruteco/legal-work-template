# Разбор документа в каталог markdown (legal-doc-splitter)

Роль для превращения исходного документа (выгрузка из КонсультантПлюс и т.п.) в удобный для работы
каталог. Сам документ целиком в контекст **не загружается**: НК РФ ч. 2 — около 1,8 млн токенов, ГК РФ ч. 1 —
около 260 тыс., даже закон об ООО — около 90 тыс. Работаем по частям: нужная статья — единицы тысяч токенов.

## Принцип

1. **Структура вместо простыни.** Документ режется по естественным границам (раздел → глава → параграф → статья),
   граница никогда не проходит внутри статьи. Файлы целевого размера до ~30 тыс. символов (~10 тыс. токенов);
   маленькие соседние статьи объединяются в один файл, большая глава становится подкаталогом.
2. **Индекс рядом.** `index.json` знает, в каком файле и в каких строках лежит каждый заголовок и сколько он весит.
   Читать можно ровно одну статью, не открывая файл целиком.
3. **Целостность проверяется.** После разбиения скрипт сверяет оглавление с найденными заголовками и строки
   исходного дерева со строками файлов. «Целостность: OK» — условие, без которого результат не используется.

## Процесс

1. **Получить исходник нужной редакции.** Сейчас читается FB2 КонсультантПлюс (инструмент
   `tools/consultant-api`, формат `fb2`, документ целиком). **Сверить редакцию**: «публичный» номер документа может
   вести на первоначальный текст; `export` клиента сам подставляет актуальную редакцию, а `edition --on-date`
   даёт редакцию на дату. В паспорте результата должна стоять редакция («ред. от …»).
2. **Разбить во временный каталог**, не в `docs/refs` (в `refs` — только после согласия пользователя, см. ниже):

   ```
   python -X utf8 .skills/legal-doc-splitter/scripts/split_document.py split <файл.fb2> --out-dir <каталог> --base LAW --n <номер>
   ```

   Параметры: `--max-chars` (по умолчанию 30000), `--name`, `--force` (перезаписывает только результат
   прежнего разбиения; чужие каталоги не трогает).
3. **Проверить вывод:** «Целостность: OK», число заголовков совпадает с оглавлением, в `README.md` каталога верные
   название и редакция. При проблемах — не использовать, разобраться.
4. **Спросить пользователя, сохранять ли в `docs/refs`** (правило AGENTS.md). Если да:
   - переложить каталог в `docs/refs/<БАЗА>-<номер>_<краткое-имя>_<дата-редакции>/`;
   - добавить запись в `docs/refs.md`: название **с редакцией**, суть, ссылка на `README.md` каталога, источник
     (КонсультантПлюс / открытый источник — по правилу AGENTS.md).
5. Решение о сохранении принимает вызвавший документ skill вместе с пользователем: сам разбор ничего в `refs` не пишет.

## Результат

```
<каталог>/
  README.md          паспорт: название, редакция, источник, объём, статус целостности, таблица файлов
  index.json         заголовки: id, уровень, вид, номер, файл, строки, размер (символы); проверки
  links.json         перекрёстные ссылки на другие документы (base, n, dst, где встретились)
  amendments.json    изменяющие акты («дата N номер»)
  00_preambula.md    реквизиты и вводная часть
  01_razdel-8/       раздел слишком велик → подкаталог: 00_intro.md + части
    01_glava-21/       …и глава может стать подкаталогом
      00_intro.md
      01_st-143--st-145.md   соседние небольшие статьи объединены
      10_st-164.md           крупная статья — отдельный файл
  assets/            изображения (формулы, схемы): img-001.png …
```

Каждый файл начинается комментарием `<!-- источник | редакция | что внутри -->`, чтобы после загрузки отдельного
файла не терялось, откуда он и какой редакции. Имена файлов — ASCII (`st-45-1`, `glava-21`, `razdel-8-1`),
порядковый префикс сохраняет порядок документа.

## Как читать (протокол экономии токенов)

1. **Никогда не загружать весь каталог и не читать документ подряд.** Начать с `README.md` (таблица файлов) или
   структуры: `python -X utf8 .../split_document.py outline <каталог> --depth 2`.
2. **Нужная статья или глава:**
   `python -X utf8 .../split_document.py read <каталог> "Статья 45"` (понимает `ст. 45.1`, `Глава 21`, `Раздел VIII`).
   Для главы-подкаталога печатается вступление и список подчинённых частей — читать нужную.
   Одинаковые номера в разных частях (параграфы, главы) → скрипт перечислит варианты, уточнить через `--id`.
3. **Нужный пункт крупной статьи:** `read <каталог> "Статья 164" --point 3`. Файлы из раздела «Крупные статьи»
   в `README.md` целиком не открывать (в НК РФ такая статья может весить ~40 тыс. токенов).
4. **Ссылка на другой документ** — искать в `links.json` (`base`, `n`, `dst`), получать документ через инструмент.
   Помнить: `n` указывает на конкретную редакцию.
5. **Редакция.** Анализ ситуации в прошлом требует редакции на дату события, а не последней (см. skills
   `bankruptcy-lawyer-rf`, `procedural-lawyer-rf`). Если в каталоге не та редакция — получить нужную и разбить заново.
6. **Примечания КонсультантПлюс** в тексте помечены `> [КП]`: это комментарий системы, не норма права. Цитируя
   норму, брать текст статьи, а не примечание; на примечание ссылаться как на примечание.

## Правила и проверки

- **Раскладка по рангу заголовков**, а не по маркерам оглавления: в оглавлении КонсультантПлюс (например, НК РФ)
  главы и статьи стоят на одном уровне. Порядок рангов: часть → раздел/приложение → подраздел → глава →
  параграф → статья. Заголовок без известного вида становится потомком предыдущего.
- **Потери недопустимы:** `index.json → validation` содержит `toc_equals_headings`, `lines_match`,
  `nodes_not_written`, `oversize_files`. Любое `false` или непустой список — повод остановиться.
- **Крупные статьи** (`oversize_files`) намеренно не режутся: статья остаётся целой, читается через `--point`.
- **Таблицы** выводятся как markdown-таблицы; таблица «Список изменяющих документов» уходит в `amendments.json`.
- **Изображения** (формулы, схемы, бланки) извлекаются в `assets/img-NNN.<ext>` и вставляются как
  `![изображение](путь/к/assets/img-NNN.png)`; пути рассчитаны от каталога файла. Содержимое формулы по картинке
  нужно смотреть отдельно (просмотр изображения), текст она не заменяет.

## Ограничения

- Читатель пока один — **FB2 КонсультантПлюс** (оглавление-якоря `#ParNN`, плоские абзацы). Другие форматы
  (HTML, DOCX, PDF, официальные публикации pravo.gov.ru) — это новые читатели, возвращающие ту же модель
  (`Doc`/`Node`); остальной код менять не нужно.
- Нет оглавления → документ целиком одним файлом (`00_preambula.md`). Для таких документов разбор по структуре
  сначала требует доработки читателя.
- Подпункты вида `1)` не выделяются в отдельные части: читаются в составе пункта/статьи.
- Оценка токенов грубая: символы / 3.

## Типичные ошибки

- Загружать в контекст целый кодекс или все файлы каталога «на всякий случай».
- Брать документ по «публичному» номеру, не проверив редакцию.
- Сохранять результат в `docs/refs` без согласия пользователя или без указания редакции и источника в `docs/refs.md`.
- Принимать `> [КП]` или список изменяющих актов за текст нормы.
- Игнорировать `oversize_files` и открывать крупную статью целиком вместо чтения по пункту.
